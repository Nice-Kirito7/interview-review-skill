# 面试复盘与项目宝典

目标：让每次真实面试形成可追溯的诊断、能开口的答案和可持续复习的积累。使用中文，技术名词按原意保留。

## 1. 确定范围与输入

读取当前任务约定、逐字稿、对应 MASTER，以及相关的最新确认记录。确认输入版本和来源；多份副本应比较内容和确认记录，不能只凭文件名选择。

按用户要求执行复盘、讨论确认、归并、训练中的相关环节。“只做阶段一二”“暂不改 MASTER”等边界继续有效；用户已授权归并时，完成可逆更新并给出差异，无需反复索取许可。仅讨论方案时交付建议。

输入不足时先完成不受影响的部分，再集中询问关键缺口。没有逐字稿时明确哪些来自摘要，不声称还原原话或覆盖全场。

涉及 MASTER 写入、拆分、项目更替或组装备战材料时，先读取 [maintenance.md](references/maintenance.md)。

## 2. 还原问答与追问链

建立时间线索引：主问题、追问、本人实际回答摘要、来源位置、初步评价。保留卡点、被打断、未回答与自我纠正；追问挂到所属主问题，同时保留独立位置。

区分转写噪声与知识错误。没有音频时按上下文标注疑似术语；没有时间戳时引用段落号。面试官的质疑是分析材料，技术对错仍需独立判断。

完成标准：每段实质提问都有回答映射或明确的缺失标记，不能只摘熟悉的问题。开场、HR、反问、公司介绍单列。

## 3. 诊断与核实

从具体片段判断：知识理解、实现/职责边界、方案取舍、证据与评测、表达及问题命中。说明哪些已答对、哪些缺失、怎样修正。不根据口述不熟推断没做过，不预测录用结果。

优先恢复“业务问题 → 我的职责 → 机制与取舍 → 验证 → 限制”的链路。结合连续追问、岗位相关性和跨面试重复卡点，选少量优先项，不制造精确总分。

核实有争议或可能过时的技术结论时，查官方文档、论文与源码，引用支持结论的页面。公共资料用于校正原理，不能证明本人项目已经采用。按需只读查代码，区分实际入口与未启用分支；静态存在不等于运行成功或效果验证。

冲突材料应标明项目、版本、时间与范围。最新明确更正可以更新口径；较新的面试原答不自动等于事实更正。未决冲突继续标记，先推进其余工作。

## 4. 提炼能开口的 QA

每题按需要包含：
- 规范题目与原始问法来源。
- 主答：直接回答，再讲必要机制与理由；通常约一分钟，随题目调整。
- 折叠追问：真实追问优先，补足输入输出、替代方案、失败分支、评测和个人贡献。推演追问注明“练习”。
- 简短诊断与证据：留在单次复盘或题末备注，不挤占主答。

主答优先自然、连贯、具体，避免每段插核验提醒。未实施、待核实、设计建议等用相关句旁的短标记，细节放折叠备注。仅修改措辞不能把“计划采用”变成“已经采用”，假设数字应保留假设属性。

项目现状题按可确认的现状作答；方案设计题可完整讲合理方案，并标记未落地范围。更完整的方案有学习价值时，可给出“方案口答〔设计，未落地〕”用于练习。事实更正用一句话交代，不让自我检讨占据正文。

原理题解释机制和适用边界；项目题由本人经历承接；开放题交代假设、权衡与验证。统一主题不等于给不同项目复制同一经历。

## 5. 沉淀与训练

逐项给出处理结果：补主答、补追问、新建题、关联公共题、仅记历史、待确认或无需变动。按维护规则更新已经授权的文件。

单次复盘保留实际回答及历史问题；MASTER 保存适合复习的当前答案。对优先问题安排具体训练，如复述调用链、核实实验记录、比较替代方案、练习连续追问。

交付说明主要发现、产物位置、MASTER 实际变动、待确认事项和下一步练习。没有进行真实逐字稿测试时，不声称流程已验证有效。

## 完成检查

- 索引覆盖主问题及追问，原答与建议答案可以区分。
- 每项负面判断有具体依据，转写疑点未当作确定错误。
- 主答可以直接复述，状态标记简短但不误导。
- 更新可追溯，稳定题号、已确认口径及有效链接得到保留。
- 重复输入不重复建题或累计次数；未授权阶段保留为提案。
